### Added

- `memory-router consolidate --dir <path> [--near-threshold <n>] [--json]` (mm-v1-T007): report-only corpus health check. No LLM, no automatic merges, never writes to the corpus (not even a temp file, verified by a directory-snapshot test both at the direct-call and CLI-subprocess level). Corpus dir resolution mirrors `test`/`eval`/`migrate`: `--dir` flag, then `$MEMORY_ROUTER_DIR`. Four independent, read-only passes:
  - **Exact dupes** (new `src/consolidate/exact-dupes.ts`): groups memories whose BODY, after normalization (trim, collapse whitespace runs to a single space, lowercase, then sha256), hashes identically. Frontmatter is not part of the comparison.
  - **Near dupes** (new `src/consolidate/near-dupes.ts`): pairwise cosine similarity over EXISTING embedding-index vectors only, no live embedding API calls. Reads `<dir>/.memory-router/index.sqlite` (built separately by `memory-router index`) via `src/embed/index-store.ts`'s public `openIndex`/`getEmbedding` API, reused read-only. Runs only when the index exists AND matches the currently active embedding provider/model, resolved the same way `src/embed/indexer.ts`'s `rebuildIndex`/`semanticSearch` do (`resolveProviderConfig({ autoDetectOllama: true })`); a missing index or a provider/model mismatch (mm-v1-T003's provenance contract, unmodified) is caught and reported as `status: "skipped"` with the exact reason, never a silent gap and never a crash. `--near-threshold` sets the cosine floor (default `0.95`); the result also reports `indexedCount`/`totalCount` so a stale index (memories added/changed since the last `memory-router index` run) is visible rather than silently under-covering the comparison.
  - **Stale references**: delegates entirely to `src/lint/stale.ts`'s existing public `lintMemoryDirForStale`, called unmodified with the same default-repo-root (`process.cwd()`) contract the `stale` CLI verb uses.
  - **Schema metrics** (new `src/consolidate/schema-metrics.ts`): `untagged` (no `topics:` at either the top level or `metadata.topics`), `legacy format` (`metadata.type` present without a top-level `type`, the exact pre-schema-v1 shape `migrate`'s `type` hoist backfills) with its rate, and `loader rejects` (files `src/memory/loader.ts` silently drops via a debug-only warning, with the actual reject reason). `src/memory/loader.ts`'s `loadMemoriesFromDir` only reports rejections through an off-by-default `debugWarn` call and, for accepted files, overwrites the raw frontmatter's `type`/`topics` with their already-resolved values before returning, so by the time a `Memory` reaches any other consumer neither the reject reason nor whether `type`/`topics` came from the top level vs. the legacy `metadata.` nesting is recoverable. `loader.ts` is out of scope for this task (forbidden to modify), so `schema-metrics.ts` duplicates its per-file frontmatter-regex + parse + validation logic read-only instead (`VALID_TYPES` itself is imported, not copied, from loader.ts's existing public export, so the type whitelist can't drift between the two independently).

  New `src/consolidate/analyze.ts` (orchestrator, `runConsolidate`) and `src/consolidate/report.ts` (text/JSON formatters, reusing `src/lint/stale.ts`'s own `formatStaleReportText` verbatim for the stale section rather than re-deriving its rendering). `cli.ts` gains the `consolidate` verb (additive only: new `--near-threshold` flag parsing with the same swallow-guard idiom as the existing `--mapping`/`--max-hits` flags, a new help block, new command dispatch reusing the existing `test`/`eval`/`migrate` `--dir`/`$MEMORY_ROUTER_DIR` resolution field). 40 new tests across `tests/consolidate-exact-dupes.test.ts`, `tests/consolidate-near-dupes.test.ts` (fixture indexes built deterministically via `openIndex`'s public API with hand-picked vectors, no live embedding calls anywhere: no-index skip, no-provider skip, provider-mismatch skip, threshold filtering, stale-index coverage reporting), `tests/consolidate-schema-metrics.test.ts`, `tests/consolidate-analyze.test.ts` (end-to-end wiring against a copied fixture corpus, plus a byte-identical directory-snapshot never-writes test), `tests/consolidate-report.test.ts` (direct formatter unit tests, same rationale as `tests/migrate-report.test.ts`/`tests/eval-format.test.ts`: a spawned CLI subprocess is invisible to `--experimental-test-coverage`), and `tests/consolidate-cli.test.ts` (dry corpus resolution, `--json` schema, `--near-threshold` validation including the swallow-guard, `--dir`/env resolution, missing-dir/nonexistent-dir errors, `--help`, and a CLI-subprocess-level never-writes snapshot even with real findings present). New fixture corpus `tests/fixtures/consolidate/corpus/` (exact-dupe pair, a unique negative control, a legacy-tagged and a legacy-untagged memory, a `verify:`-stale reference, and two loader-reject shapes). A finding surfaced while verifying this fix empirically, not assumed: SQLite's WAL protocol means ANY connection, including a genuinely readonly one, that reads a WAL-mode database still needs to create `-wal`/`-shm` sidecar files on first read, since the file's own on-disk journal mode is already WAL (every index this pass is pointed at already is, `memory-router index` always sets it); a readonly connection additionally cannot checkpoint on close, so those sidecars are left behind, while a writable connection actually cleans them up on close. `readonly: true` therefore does NOT reduce filesystem footprint versus the pre-fix code (verified directly: both leave `index.sqlite` itself byte-identical against the fixtures probed); its real, load-bearing effect is that a write attempt through the returned store (`upsert`/`remove`) is now rejected by SQLite itself ("attempt to write a readonly database") instead of silently succeeding, protecting a concurrently-used index against a future bug here (proven behaviorally by 4 new `tests/index-store.test.ts` tests: write-rejection, the provider-mismatch throw still fires on a readonly open, a readonly open against a missing file throws cleanly instead of creating one, and omitting `readonly` keeps every existing read-write callsite unaffected). Because that write-rejection is the only externally observable effect of the flag, and `near-dupes.ts`'s own happy-path/skip-path return values and the index file's bytes are unchanged either way whether the flag is passed or not (confirmed by direct experimentation), the dedicated mutation-proof test for `near-dupes.ts`'s own wiring is a source-level regression guard (asserts the literal `readonly: true` text is present in its `openIndex` call) rather than a behavioral one.

- `memory-router migrate --dir <path> [--apply] [--mapping <file>] [--json]` (mm-v1-T006): mechanical, idempotent frontmatter backfill to schema v1 (`name`, `description`, top-level `type`, `topics: [...]` with >=1 entry, `created`). No LLM, no guessing: whatever isn't mechanically derivable stays untouched and is surfaced in the report (`untagged topics` / `missing type`) instead of invented. Dry-run by default; `--apply` writes. Only `*.md` files are scanned, `MEMORY.md` and non-`.md` files (`topics.yml`, `golden.yml`, ...) are never touched. Corpus dir resolution mirrors `test`/`eval`: `--dir` flag, then `$MEMORY_ROUTER_DIR`. Three independent, additive-only rules, none of which ever overwrites an existing canonical value:
  - `type`: hoists `metadata.type` to top-level `type`, only when no valid top-level `type` exists and the value is one of the four known `MemoryType`s (`VALID_TYPES`, reused read-only from `src/memory/loader.ts`).
  - `topics`: derived from, in order, (1) `metadata.topics`, HOISTED verbatim (byte-identical values, no trim/dedupe/reorder) when it's a non-empty array of strings, analogous to the `type` hoist above; added after an implementer flag on this same task: the loader (`src/memory/loader.ts`) already reads `metadata.topics` liberally as a second topics source (`fm.topics ?? fm.metadata?.topics ?? []`) since mm-v1-T002, and a small number of real corpus files (4 at the time of writing) carry curated topics only there, so `migrate` must canonicalize them, not discard and re-derive; an invalid shape (not an array, or an array with a non-string entry) is never hoisted and falls through to the next step rather than crashing, (2) a curated `--mapping` file (new `src/migrate/mapping.ts`: a top-level YAML list of `{id|prefix, topics}` rules, first-rule-wins, mirroring `topics.yml`'s bare-list shape rather than introducing a second file convention), (3) a vocabulary pattern match (`matchedTopicsForVocabulary`, reused read-only from `src/vocab/loader.ts`, so a corpus's own `topics.yml` override applies) against `name`+`description` **only**, never the body. No match at any step leaves the file untagged. The report (`src/migrate/report.ts`) makes the resolved state visible via `action`/`source`: kept (existing top-level topics), hoisted (`source: "metadata.topics"`), mapped (`source: "mapping"`), derived (`source: "vocabulary-pattern"`), or untagged (`action: "missing"`, text/`--json` both render `untagged`); the untagged text line was reworded from "no mapping/vocabulary match" to "no metadata.topics/mapping/vocabulary match" to name all three consulted sources.
  - `created`: stamped from the file's mtime (`YYYY-MM-DD`), marked `# approx (mtime)` so it reads visibly as an approximation, only when no `created` key exists yet.

  Frontmatter is parsed and re-serialized with `yaml`'s Document API (`parseDocument`/`doc.toString()`) rather than a plain-object round-trip: this preserves existing key order and comments and only appends new fields (long scalars may still be re-wrapped and trailing whitespace is normalized; see the fix-round 2 note below for the `lineWidth: 0` correction), and lets the `created` field carry its `# approx (mtime)` comment. A file with nothing to change is never rewritten at all (not even a no-op serialize), which is what makes a second `--apply` run byte-identical rather than relying on round-trip fidelity for untouched files. Read-only presence/value checks work off `doc.toJS()` (a plain JS object) rather than `doc.get(...)` directly, since `.get()` auto-unwraps a scalar to a plain value but returns the internal `YAMLSeq` node (not a plain array) for a `topics:` list; an early version of this change used `doc.get('topics')` directly and silently misclassified every already-canonical `topics:` list as absent, caught by the "already canonical" and "untagged" tests going red during development, not by review.

## [0.2.0] - 2026-05-05

### Added

- `lint --conflicts --semantic` (#30): embedding-cosine upgrade for paraphrased opposite-polarity pairs the regex pass misses ("always squash before merge" vs "never squash, use fast-forward only"). Reuses the live `index.sqlite` when available; embeds misses on the fly without persisting. Fail-open with a stderr warning when `OPENAI_API_KEY` is unset, so CI without secrets stays green.
- `lint --conflicts --json` (#32): machine-readable report mirroring the `--drift --json` contract. Schema: `{ scannedCount, feedbackCount, hits: [{ severity, topic, reason, a, b }] }`. When combined with `--drift --json`, drift owns stdout and conflicts routes to stderr so a single CI step can pipe both fds.
- Extended polarity vocabulary (#32): formal-register markers `mandatory`, `mandate`, `compulsory`, `prohibit`, `forbid`, `disallow`, `cannot` (plus inflections), so memories written without `ALWAYS`/`NEVER` still classify and still get filtered out of subject-token Jaccard.
- `stale --repo-root <p>` repeated, and variadic `stale --repo-roots <p1> <p2> ...` (#33): multi-repo workspace mode for the stale linter. A ref is STALE only when none of the roots resolves it; first hit wins. The single-root detail format is preserved for v1 CI scrapers; multi-root emits a single-line aggregated summary. `symbolCheckDegraded` is `true` only when every probed root is non-git.
- Date-staleness pass (#34): every memory whose newest ISO date in the body is more than 90 days old AND whose frontmatter has no newer `updatedAt:` is flagged `possibly-stale`. INFO-only, never blocks CI.
- `stale --check-urls` (#34): HEAD-request every external URL extracted from the body. `4xx` → STALE; `5xx` and network errors → `skipped`; `2xx`/`3xx`-following → silent. 5-second timeout. Off by default because it's network-dependent.

### Changed

- Polarity detection scope (#31): lowercase markers (`always`, `never`, `prefer`, `avoid`, ...) now only fire against the first two whitespace-separated tokens of the line; ALL-CAPS variants still match anywhere. Mixed polarity is still detected when a leading directive is contradicted later on the line. The Jaccard subject-overlap floor was lowered from `0.25` to `0.15` now that descriptive mid-sentence false positives are filtered upstream.
- Debug stderr prefix unified to `[memory-router]` (#29): both the loader's rejection warnings and the indexer's query-cache observability share one bracketed prefix; `grep '^\[memory-router\]'` now catches every gated diagnostic.

### Schema

- v1 → v2 migration (#35): adds `model TEXT` column to the `entries` table. Embeddings are now stamped with the producing model so `semanticSearch` (Confidence Gate) and `lint --conflicts --semantic` cannot silently mix vectors from incompatible embedding spaces. The migration is idempotent (PRAGMA `table_info` probe before `ALTER`), so opening a 0.1.x index file just adds the column; pre-v2 rows survive with NULL model. The next `semanticSearch` open emits a one-line stderr warning recommending `memory-router index <dir>` to refresh; once rebuilt, every row carries the active `MEMORY_ROUTER_EMBED_MODEL`.

### Compatibility

- API change: `IndexStore.upsert(id, mtime, embedding)` is now `upsert(id, mtime, model, embedding)`. `getEmbedding(id, expectedModel?)` and `search(query, k, expectedModel?)` accept an optional model filter that rejects cross-model rows (and pre-v2 NULL rows). Direct programmatic callers of `IndexStore` need to pass a model name; hook / CLI / MCP users see no behaviour change beyond the upgrade-path warning above.

## [0.1.0] - 2026-05-05

First public release.

### Added

- **Three-gate router**: deterministic memory injection for Claude Code, gated by topic dictionary, tool-call regex, or a fallback ambiguity-driven semantic match.
- **Hook binaries**: `memory-router-user-prompt-submit` and `memory-router-pre-tool-use` consume Claude Code's hook stdin contract and emit `hookSpecificOutput.additionalContext` on stdout.
- **MCP server** (`memory-router-mcp`) exposing `memory_search`, `memory_resolve`, and `memory_apply` for imperative checks.
- **CLI** (`memory-router`) with subcommands:
  - `tag` to propose `topics:` / `severity:` frontmatter for legacy memories.
  - `index` to build a sqlite-vec embedding index, including an LRU query-embedding cache.
  - `lint` with three checks: `--drift` (MEMORY.md vs. on-disk corpus), `--unknown-topics` (typos against the topic registry), `--conflicts` (opt-in: pairs of feedback memories with topic overlap and opposite-imperative directives).
  - `stale` to flag broken path / symbol references in memory bodies. `verify:`-frontmatter-only by default; `--scan-body` opts in to body-regex extraction.
- **Schema-versioned sqlite index**: `meta.schema_version` row + migration framework, so future on-disk shape changes have a clean upgrade path.
- **Frontmatter `verify:` contract**: memories declare claims about the repo state. The runtime side prefixes a stale warning when the claim no longer holds; `memory-router stale` checks the same claims proactively.
- **Observability**: `MEMORY_ROUTER_DEBUG=1` emits one stderr line per rejected memory file (broken YAML, missing required field, etc.) without touching stdout.

### Compatibility

- Node 22 or newer.
- Native dependencies: `better-sqlite3` and `sqlite-vec`. The CI smoke step verifies they load before tests run.
